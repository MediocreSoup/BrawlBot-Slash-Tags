# BrawlBot Slash Tags

This README was generated by GPT 5.6 luna.

A Red-DiscordBot cog that provides a persistent, guild-scoped tag system through slash commands and optional prefix commands.

## Features

* Persistent tags stored through Red's `Config`
* Tags organised into categories
* `/tag` slash command
* Optional prefix-based tag invocation
* Ordered `{argument}` placeholders
* Whitelisted `[interaction.*]` references for slash tags
* Raw text or embed output
* Discord message-link importing
* Image attachment importing
* JSON import
* Automatic JSON backups
* 20 most recent backups kept per guild
* Tag and category names automatically converted to lowercase
* Tag and category names limited to 100 characters
* Tag names are globally unique within each guild

## Installation

This cog is intended for an existing Red-DiscordBot instance.

```text
[p]repo add BrawlBot-Slash-Tags https://github.com/MediocreSoup/BrawlBot-Slash-Tags
[p]cog install BrawlBot-Slash-Tags BrawlBotSlashTags
[p]load BrawlBotSlashTags
[p]slash sync
```

> **Note:** Slash commands can take some time to appear in Discord after syncing. If they do not appear immediately, wait a little and run `[p]slash sync` again.

For BrawlBot, the normal prefix is `.`.

## Retrieving tags

Tags are stored inside categories, but tag names themselves are unique across the entire guild because prefix commands do not include a category.

For example:

```text
/tag category:newtohelpchat tag:dontasktoask
/tag category:packages tag:profilestore
/tag category:newtoscripting tag:workspace
```

With prefix commands enabled, the same tags can be invoked with:

```text
.dontasktoask
.profilestore
.workspace
```

Prefix tags are resolved without a category. Because of this, a tag name may only exist once anywhere in the guild's tag database.

### Tag and category names

Names are automatically:

1. Trimmed
2. Converted to lowercase
3. Limited to 100 characters

For example:

```text
MyCategory -> mycategory
 MyTag      -> mytag
```

The same normalization is applied when using slash commands.

## Managing tags

Management commands are slash-only and require Redbot admin permissions or Discord administrator permissions.

Examples:

```text
/managetags add_category category:newtohelpchat

/managetags add_tag
    category:newtohelpchat
    tag:dontasktoask
    value:https://dontasktoask.com/
    embed:true

/managetags edit_tag
    category:newtohelpchat
    tag:dontasktoask
    value:https://example.com/
    embed:false

/managetags delete_tag
    category:newtohelpchat
    tag:dontasktoask

/managetags rename_tag
    category:newtohelpchat
    tag:dontasktoask
    new_tag:example

/managetags rename_category
    category:newtohelpchat
    new_category:help

/managetags move_tag
    category:newtohelpchat
    tag:dontasktoask
    new_category:help

/managetags list category:newtohelpchat

/managetags delete_category category:newtohelpchat

/managetags set_tag_embed
    category:newtohelpchat
    tag:dontasktoask
    embed:false
```

`add_tag` creates a new tag. Use `edit_tag` to change an existing tag.

### Enabling prefix commands

Prefix tag commands are enabled by default.

They can be enabled or disabled per guild:

```text
/managetags toggle_text_commands enabled:true
/managetags toggle_text_commands enabled:false
```

Disabling prefix commands does not affect `/tag`.

## Tag output

Tags default to embed output.

To make a tag send plain text instead:

```text
/managetags set_tag_embed category:example tag:hello embed:false
```

A tag can also be stored in JSON using:

```json
{
  "value": "Hello!",
  "embed": false
}
```

Plain-text output is automatically split into multiple messages when necessary.

Embed output is split into multiple embeds when the description would exceed Discord's embed description limit.

## Discord message links

`add_tag`, `edit_tag`, and `preview_embed` accept Discord message links.

For example:

```text
/managetags add_tag
    category:examples
    tag:hello
    value:https://discord.com/channels/123/456/789
    embed:true
```

When a message link is resolved:

* A message with text uses the message content.
* An image-only message uses the raw attachment URL.
* An embed-only message cannot be imported as a tag value.
* Uncached channels are fetched when possible.

### Image-only messages

For an image-only message, the attachment URL is stored directly.

With:

```text
embed:true
```

the URL is placed into the tag embed.

With:

```text
embed:false
```

the raw image URL is sent as normal Discord text, allowing Discord to render the image.

## Tag arguments

Tags can contain ordered placeholders such as:

```text
Hello {name}, welcome to {city}!
```

Arguments are supplied in the same order as the placeholders.

For example:

```text
/tag category:welcome tag:greet arguments:"Ava \"Paris, France\""
```

This resolves to:

```text
Hello Ava, welcome to Paris, France!
```

Quoted arguments can contain spaces.

All expected arguments must be provided, and extra arguments are rejected.

### Literal braces and brackets

Prefix/special syntax can be escaped with backslashes:

```text
\{name}
\[interaction.user.name]
```

## Interaction references

Slash tags can use a small whitelist of interaction values.

The supported top-level objects are:

```text
interaction.user
interaction.guild
interaction.channel
```

The supported leaf attributes are:

```text
name
id
display_name
mention
nick
global_name
```

Examples:

```text
[interaction.user.name]
[interaction.user.id]
[interaction.user.display_name]
[interaction.user.mention]

[interaction.guild.name]
[interaction.guild.id]

[interaction.channel.name]
[interaction.channel.id]
```

Not every leaf attribute exists on every object. For example, `nick` and `global_name` are user/member properties, while `guild` and `channel` have their own available attributes.

The whitelist deliberately prevents arbitrary traversal such as:

```text
[interaction.client.http.token]
```

### Prefix commands and interaction references

`[interaction.*]` references are **not supported in prefix tags**.

For example, a tag containing:

```text
Hello [interaction.user.name]
```

will work with:

```text
/tag ...
```

but invoking the same tag through a prefix command will return an error explaining that interaction references are slash-only.

This is intentional because prefix tags do not have a Discord `Interaction` object.

## JSON import

Tags can be imported from either a JSON string or an attached JSON file.

Example:

```text
/managetags import_json
    json_data:{"examples":{"hello":"Hello world!"}}
```

Or upload a JSON file:

```text
/managetags import_json attachment:[your JSON file]
```

The JSON format is:

```json
{
  "category": {
    "tag": "value"
  }
}
```

Plain-string values use embed output by default.

For explicit plain-text output:

```json
{
  "category": {
    "tag": {
      "value": "Hello world!",
      "embed": false
    }
  }
}
```

Imported category and tag names are subjected to the same normalization rules as normal tag creation.

Imports reject:

* Empty category names
* Empty tag names
* Names longer than 100 characters
* Duplicate tag names across categories
* Duplicate tag names created by case differences

Importing a tag with the same name into the same category replaces that tag's existing value.

Importing a tag that already exists in another category is rejected.

## Backups

Every modification creates a JSON backup in Red's cog data directory.

Backups are stored per guild and include a UTC timestamp with microsecond precision.

Only the 20 most recent backups for each guild are retained.

## Permissions

Management commands require one of:

* Redbot owner
* Redbot admin
* Discord administrator permission

Normal tag retrieval does not require management permissions.

## Notes

Tags are scoped to individual guilds.

Tag names are globally unique within a guild because prefix invocation does not include the tag category.

Slash commands can still explicitly specify the category:

```text
/tag category:example tag:hello
```

Prefix commands use only the tag name:

```text
.hello
```

If a tag name contains whitespace, it can still be accessed through `/tag`, but it cannot be invoked as a single prefix command name.
